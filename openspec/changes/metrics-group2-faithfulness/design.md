# Design: 2.2 faithfulness — citation condition + validated judge

## Context

- reading-400 manifest (`data/eval_set_manifest.csv`, 400 items, 200 Vi-SQuAD +
  200 Vi-DROP, seed 42) is the frozen eval set; gold lives in
  `data/gold/review_gold_agreed.csv` for scoring.
- The frozen reading pipeline: `run_reading_eval.py` (`build_reading_prompt`,
  checkpoint `reading_result_<n>_<slug>.csv`) → `score_reading_eval.py`
  (EM + char-F1). The 65K arm-A baseline on this set (MC-31): EM 72,25%.
- Judge endpoints available today: IEC internal (`Qwen3.5-9B-65K`, also
  `-28K`/`-125K` listed) and OpenCode Zen Go (`MiMo V2.5`, token in
  `.omp-mimo/.env`, used by MC-30).
- Plan stop condition (group 2.2): validate the judge on 50–100 human-labeled
  items before trusting any faithfulness number.

## Decisions

### D1 — Condition and namespace
Model `Qwen3.5-9B-65K` @ IEC internal (the only node with a full arm-A
baseline). Outputs carry the label slug `Qwen3_5-9B-65K-cite` (`--label`, the
harness-arm precedent: `--model` stays the endpoint model name, the label
names the condition). Files: `reading_cite_answers_<label>.csv`,
`reading_cite_scores_<label>.csv`, `reading_cite_summary_<label>.csv`. Never
compared row-to-row with MC-31's reading-400 (different prompt); the card
states this in one line.

### D2 — Prompt (bytes pinned in MC-37 before any call)
New builder `build_citation_prompt(context, question)` in the new runner;
`build_reading_prompt` is not touched. Shape (Vietnamese, final bytes frozen
in the card):

```
Đọc đoạn văn dưới đây và trả lời câu hỏi.
Trả lời ngắn gọn bằng một cụm từ hoặc con số lấy từ đoạn văn.
Sau đó trích dẫn NGUYÊN VĂN một đoạn ngắn trong bài chứa câu trả lời.

Đoạn văn:
<context>

Câu hỏi: <question>

Trả lời: 
Trích dẫn: 
```

Inference flags: temperature 0, seed 42, `max_tokens=128` (answer+citation;
48 was the answer-only budget), workers 4. These are the card's condition.

### D3 — Extraction (frozen for this condition, fail-soft)
Parse the LAST occurrence of each label (`Trả lời:` / `Trích dẫn:`); answer =
first non-empty line after `Trả lời:` up to `Trích dẫn:`; citation = text after
`Trích dẫn:` to end, stripped. Missing/empty field → empty string, counted
unparsed, **never repaired** (repo rule). A pure `extract_citation_answer(raw)
-> (answer, citation)` with table tests, mirroring `extract_answer`'s style but
its own contract.

### D4 — Judge instrument
- `judge_faithfulness.py run --endpoint ... --judge-model ...`: one call per
  item with a pre-registered prompt asking whether the citation supports the
  answer **given the context**; output must be JSON
  `{"verdict": "supported" | "unsupported", "reason": "<ngắn>"}`. Parse strict
  JSON; unparsable judge output → `judge_error`, counted, never guessed.
  Temperature 0, seed 42, `max_tokens=200`; raw judge response stored verbatim
  per item; judge model + endpoint recorded per row and in the summary.
- **Judge model choice**: recommended primary `MiMo V2.5` (Zen Go) — an
  independent family, so a verdict is not the model grading itself. Fallback
  `Qwen3.5-9B-65K` (IEC) only if Zen is unavailable; then the card carries the
  self-judge caveat in bold. The judge endpoint gets its own preflight.
- Mechanical companion (no judge): `citation_verbatim` = normalized citation
  is a substring of the normalized context. Reported next to the judge verdict,
  never merged with it: verbatim ≠ supports.

### D5 — Validation gate (before any full judge pass)
- Sample: 60 items, seed 42, stratified 30 Vi-SQuAD + 30 Vi-DROP and 30
  EM-correct + 30 EM-incorrect (pre-registered rule; the sheet is generated by
  the tool, labels are human).
- The labeler sees (question, context, answer, citation) and answers
  yes/no "citation supports the answer"; the judge's verdict is **not** shown
  (blind sheet; judge verdicts for these items are revealed only after labels
  are frozen in a tracked file).
- Gate: raw agreement ≥ 80% **and** Cohen's κ ≥ 0.6. Fail → one documented
  judge-prompt iteration, re-validate on the same frozen human labels. Fail
  again → STOP: publish the instrument-failure result (agreement numbers),
  no faithfulness score, and record the gap.
- Agreement math is a pure function with unit tests (confusion matrix, κ).

### D6 — Metrics (definitions frozen in MC-37)
| Metric | Definition |
| --- | --- |
| `compliance` | both fields non-empty / n |
| `em`, `char_f1` | frozen `score_pair` on the extracted answer vs gold |
| `citation_verbatim` | normalized citation ⊆ normalized context |
| `judge_supported` | verdict == "supported" / judged n (errors excluded, counted) |
| `correct_and_supported` | EM=1 ∧ supported — the headline "grounded correct" |
| cross-tab | correct×supported 2×2 (+unparsed/judge_error buckets, never folded) |

### D7 — Cost and ordering
400 answer calls (~10–20 min at workers 4) + 60 validation + 400 judge calls
(~15–30 min). Order: pre-register MC-37 → answers run → score (frozen) →
generate blind sheet → human labels committed → validation gate decision
(MC-38 part 1) → full judge pass → metrics (MC-38 part 2). Any gate failure
stops before the full pass.

## Risks

| Risk | Mitigation |
|---|---|
| Judge agrees with humans by chance | κ gate alongside raw agreement; stratified sample; blind sheet |
| Self-preference if judge = model under test | primary judge is MiMo (independent family); 65K fallback carries the caveat |
| Citation format non-compliance drags everything | compliance is its own reported metric; unparsed counted, never repaired |
| Judge endpoint flaky (IEC history) | preflight per step; `--resume`; judge model pinned per card |
| Scope creep into ViHallu/safety | non-goals in the proposal; group 4 stays a documented gap |
