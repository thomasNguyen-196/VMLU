# MC-103 — MiMo V2.6 Flash (OpenCode Go), weakness map on the MC-95 calibration items

Registered 2026-10-30 (+07) before benchmark-item requests of this card. The design is `openspec/changes/diagnostic-router-loop`, Phase 2 (decision 6, task 2.0). It does not change MC-90 to MC-102: their registered text, manifests, rules and analyses stand.

| Field | Condition |
| --- | --- |
| Why | **The owner's goal.** The router loop must serve many student models. Each model would share one loop procedure and keep its own weakness map: which fix helps on which dataset. On 2026-10-30 the owner chose MiMo V2.6 Flash as the first API student.<br>**What is known for Qwen3.5-9B.** On VMLU and VM14K, S beats B by about 7 to 12 points (MC-94, MC-95). On ViBidLQA the arms differ by a few token-F1 points, and Q helps nowhere (MC-97).<br>**What this card asks.** Is the best fix per dataset the same for a different model, one that thinks by default?<br>**Why these items.** The items are the 180 calibration items of MC-95, where Qwen already answered B and S twice. The two maps then compare item by item, with no Qwen request. |
| Student / route | MiMo V2.6 Flash (`mimo-v2.6-flash`, profile `mimo-v2-6-flash`) on the direct OpenCode Go chat-completions API, host `opencode.ai`, non-streaming.<br>• The system prompt is `Answer the user's question.`, as in the Qwen campaign.<br>• Temperature, reasoning effort and seed are omitted, so the provider defaults apply (thinking mode; the profile lists temperature 1.0).<br>• `max_completion_tokens=20000`, as MC-85; 300 s timeout; no SDK retries.<br>• The credential comes from the local OpenCode auth store and is never written to outputs. |
| Items | The 180 calibration items of the router v3 held-out set (MC-95; manifest self-hash `e4780be9850f14797cff81a67e40181ab99fc377f83349812d635e0038f370e7`): VMLU valid 60, VM14K four-option 60, ViBidLQA train 60. |
| Arms | • **Every item:** B twice (`B-r1`, `B-r2`) and S once (`S-r1`). Their prompts are MC-95's byte for byte, checked by prompt hash.<br>• **The 60 ViBidLQA items:** Q once (`Q-r1`, the MC-97 builder).<br>Total 600 attempts (B 360, S 180, Q 60).<br>• **Files.** Configuration `data/diagnostic_router_loop/weakness_map_v1.json`, SHA-256 `afa923ded912218e3ad518cd4350f53593c8c14646643ef5ad98dbd4f7ab7e60`. Manifest `weakness_manifest_v1.json`, self-hash `18ea6429f093976d1185573f5f4b30701cad9255e54b927e38584c4e46518623`. |
| Scoring | The frozen per-arm scorer of the diagnostic campaign (`diagnostic_prospective.score_arm_rows`). B is scored on the raw reply, S and Q on the line after the last final-answer label. Multiple choice uses accuracy; reading uses token-F1, with exact match beside it. |
| Limits | • At most 4 requests in flight; a breaker after 4 consecutive network failures; a budget of 6,000,000 reported tokens (expected 0.3 to 2 million, depending on how much MiMo thinks).<br>• **Halts.** The run halts on an authentication error. It also halts when a completed response reports a model id without `mimo`, or a model id different from the first one reported. A response that reports no model id is recorded and not checked.<br>• **Resume.** Completed responses, including truncated ones, are terminal; `--resume` re-sends only attempts without one. |
| Gates | Execution requires all of: the `MC-103` heading in `measurement_card.md`; this detail card; `data/diagnostic_router_loop/registration_weakness_map.json` with the configuration and manifest SHA-256 above; and the route resolving to the registered host and model. The runner rebuilds the manifest from the MC-95 sources and refuses to run when it differs. |
| Analysis (fixed before data) | `analyze_weakness_map`, plan `weakness-map-v1`, run once. It compares MiMo, per dataset, with Qwen on the same items (Qwen's MC-95 `B-r1`, `B-r2` and `S-r1`, scores SHA-256 `9624af66c5f02f2a41080810f9396b588773e9d9eb4d8fd9bd98cca71a51f52e`; `S-r2` is not used).<br>• **Arm means.** Draw-1 arm means, B's second draw, and the rule loop: B-r1 when it agrees with B-r2 under `normalized-answer-v1`, otherwise S-r1.<br>• **Each fix against B-r1.** The mean paired difference with a percentile bootstrap interval (2,000 resamples, seed 7) and a two-sided sign-flip p-value (20,000 resamples, seed 7). Also the rescued items (B-r1 wrong, fix right) and the damaged items (B-r1 right, fix wrong), where right means a correct letter or a token-F1 of at least 0.5.<br>• **Noise.** How often B-r1 and B-r2 agree, and their paired difference.<br>• **Two maps per model.** The point map takes the arm with the highest draw-1 mean, keeping B unless a fix beats B-r1 by at least 1.0 point. The reliable map takes a fix only when its paired gain's 95% interval lies above zero. The report lists the datasets where the two models' maps differ.<br>• **Interaction.** MiMo's S-r1 minus B-r1 against Qwen's, item by item, with the same interval and p-value.<br>• **Description.** Finish reasons, truncation, S and Q format compliance, response model ids, reasoning tokens, reported tokens, and the list-price cost from the profile (prices checked 2026-10-06).<br>No test decides anything here: the maps are descriptive inputs for the router loop. The report's top-level keys are recorded in the registration and checked. |
| Provenance and outputs | `condition.json` holds the configuration, manifest, MC-95 manifest, prompt-template, Q-protocol, scorer, engine, module, runner and card hashes, the route and the limits. Also kept: `attempts.jsonl` (raw replies and usage), `predictions.jsonl`, `scores.jsonl`, `summary.json`, `run.json` and `operator_events.jsonl`. All sit under `all_res/diagnostic_router_loop/weakness_map/mimo-v2-6-flash/`. The analysis writes `analysis/weakness_map_report.json` and `analysis/weakness_maps.json`. Nothing is uploaded. |
| Comparison limits | • **Small samples.** Sixty items per dataset give wide intervals. In MC-95, 60 calibration items chose the wrong arm on VM14K.<br>• **One S draw.** MiMo has one S draw per item, so S's own noise is not measured.<br>• **Route and settings.** Qwen's answers come from 2026-10-27, on its own route: IEC, Responses API, a 4,096-token cap, no thinking. A model difference here is therefore also a difference in route and settings.<br>• **Prior exposure.** MiMo answered the VMLU items before (MC-85). It keeps no memory across requests, but exposure in training to these public datasets cannot be measured.<br>• **Q.** Q is measured only for MiMo. Qwen's Q results are on other items (MC-97). |

The resumed runs kept the frozen condition; only the runner hash, an implementation field, changed.<br>• **Launch 2** (`--resume`, 11:08:35–11:45:50 +07). 597 of 600 attempts completed; 3 timed out at 300 s.<br>• **Launch 3** (`--resume`, 11:46:28–11:51:20 +07).
