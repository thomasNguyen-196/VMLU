# MC-117 — omp 18.0.0 with dsh's system prompt (OMPS) for Qwen3.5-9B (IEC) and MiMo-V2.6-Flash (OpenCode Go) on MC-115's 646 items (246 MC, 400 closed-book ViBidLQA), two draws: does omp's default system prompt carry the model × harness interaction?

Registered 2026-11-20 (+07), before any benchmark-item request of this card. The design is in `openspec/changes/diagnostic-legal-agent-omp-prompt`. On 2026-11-20 the owner made these choices:
- **The research direction.** The interaction between model and harness ("tôi nghĩ chúng ta nên nghiên cứu sâu vào sự tương tác giữa model và harness").
- **The component to test first.** omp's system prompt ("okay làm 3 đi").
- **The design** ("okay"), with an addition: observe each harness's flow log, because the actions a harness performs are what set it apart ("quan trọng là ta phải quan sát flow log của harness đó … cái quan trọng là actions nó thực hiện").
- **The build** ("yes") and a 4-attempt smoke test ("chạy smoke test đi").

This card does not change MC-90 to MC-116: their registered text, manifests, rules, analyses and conclusions stand. Their modules are imported, not edited. The one shared-code change adds the arm id `OMPS` to `diagnostic_prospective.ARMS` (appended, scored like OMPF), as MC-112 to MC-114 added DSH, DSHF, OMPF and C.
