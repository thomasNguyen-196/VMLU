# MC-110 — MiMo V2.6 Flash (OpenCode Go), the self-improvement loop on VMLU test, asked round by round

Registered 2026-11-07 (+07) before benchmark-item requests of this card. The design is `openspec/changes/diagnostic-router-loop`, task 2.10. It does not change MC-90 to MC-109: their registered text, manifests, rules and analyses stand.

| Field | Condition |
| --- | --- |
| Why | **The owner's request.** On 2026-11-07 the owner asked to start MiMo ("bắt đầu Mimo"), the other half of the VMLU Test column of the /table before-and-after table (`docs/router-before-after/README.md`). Qwen's half is MC-109.<br>**What is known.**<br>• On VMLU valid, MC-105's loop lifted MiMo from 77.8% (its within-run B) to 83.2% (Holm p below 0.001).<br>• On VMLU test, MC-109's loop lifted Qwen from 67.09 to 76.63 on vmlu.ai.<br>**What this card asks.** What the same loop gives MiMo on the 9,833 test items, as vmlu.ai scores the before and the after. |
| Student / route | **MiMo V2.6 Flash** (`mimo-v2.6-flash`, profile `mimo-v2-6-flash`) on OpenCode Go (host `opencode.ai`), with MC-105's MiMo request (the MC-103 route), the same for B and S:<br>• chat completions, not streamed, system prompt `Answer the user's question.`;<br>• temperature, seed and reasoning effort not sent (provider defaults);<br>• 20,000 completion tokens, 300 s timeout, no SDK retries;<br>• one routing session per attempt (`x-opencode-session`, named `vmlu-mc110-…`).<br>The credential comes from the local OpenCode auth store, as in MC-105, and is never written to outputs. |
| Items | The 9,833 VMLU test items of MC-109, with the items and prompts of the /table VMLU Test runs. Every item is checked row by row, prompt included, against the frozen v2 VMLU manifest (`data/vi_multimodel_v2/vmlu_v2.json`, self-hash `553fbd77e318eade604911998251e3a32abf743577c28101f8698632eef6b24a`). Gold is withheld; only vmlu.ai scores the split. MiMo answered these items before in MC-63 (OMP without tools), MC-85 (direct API) and MC-89 (OMP full tools); no router card used them for MiMo. |
| Arms | **B:** the frozen v2 VMLU prompt, byte for byte the /table VMLU Test prompt, asked twice (B-r1 and B-r2) as in MC-105.<br>**S:** the campaign step-by-step template of `data/diagnostic_prospective_v1/prompt_templates_v1.json`; every S prompt is byte for byte MC-109's.<br>**Possible attempts:** B-r1, B-r2, S-r1, S-r2 and S-r3 per item, 49,165 in all.<br>**Files.** Configuration `data/diagnostic_router_loop/vmlu_test_loop_mimo_v1.json`, SHA-256 `b52c04fb554f7d6f048b190fc3bdaaef5bdf6507d83c32f5a4cc235c53b50c77`. Manifest self-hash `68c38f7e91df8e45244d60510ad2f8a56007727d6f908dbaf52f8213aae5d33b`. Only the hash is frozen: the runner rebuilds the manifest, refuses to run when its hash differs, and writes the copy it ran with into the outputs. |
| The loop | MC-104's and MC-105's rule for MiMo's multiple choice, unchanged:<br>• **Round 1.** Keep B-r1 when B-r1 and B-r2 agree.<br>• **Round 2.** Otherwise keep S-r1 when it agrees with one of them.<br>• **Round 3.** Otherwise take the majority of S-r1 to S-r3. A tie goes to the earliest; an empty answer casts no vote; with no answer, S-r1 is final.<br>• **Agreement:** router v2's normalized-answer-v1. Both parsed letters must be non-empty and equal.<br>The final answer is always one of MiMo's own logged answers. |
| Schedule | As in MC-109, **each attempt is asked only when the rule needs it**:<br>• B-r1 and B-r2 for every item;<br>• S-r1 only when B-r1 and B-r2 do not agree;<br>• S-r2 and S-r3 only when S-r1 agrees with neither.<br>The attempts are independent requests, so the final answer is the one MC-105's replay (`diagnostic_table_loop.choose`) would choose from the same attempts; the tests check this on 3,000 random cases. The attempts the rule never needs are not sent, so there is no always-S or always-vote policy here.<br>**Passes.** Each pass sends every attempt the rule needs, given the completed attempts so far. An attempt without a completed response (a technical failure, not a fatal one) is sent again in the next pass. A launch stops after 6 passes, after a pass that completes nothing, or at a fatal row; `--resume` continues from the ledger. No pass sends one attempt twice or re-sends a completed one: the runner fails closed if it would, the engine hands each attempt to exactly one lane under a lock, and one output admits one launch at a time (file lock). |
| Scoring | The frozen letter parser. B is parsed from the whole reply, as MC-105 scored B. S is parsed from the line after the last final-answer label, as in the campaign. A truncated or unparsed reply is an empty answer. |
| Limits | • **In flight:** at most 6 requests, MC-105's registered value for MiMo; the owner chose it on 2026-11-07 over 12 (MC-85).<br>• **Breaker:** after 4 consecutive network failures.<br>• **Budget guard:** 20,000,000 reported tokens. This is projected from MC-105's MiMo VMLU valid rounds and usage: about 7.7 million for the two B answers and 2–4 million for S. Expected duration at 6 in flight: about 9 hours of B and 2–4 hours of S.<br>• **Halts.** On an authentication error, a permanent provider error, a tool call, a model-identity drift, the budget or the breaker, as in MC-105.<br>• **Resume.** Completed responses, including truncated ones, are terminal. |
| Gates | Execution requires all of: the `MC-110` heading in `measurement_card.md`; this detail card; `data/diagnostic_router_loop/registration_vmlu_test_loop_mimo.json` with the configuration's SHA-256 and the manifest self-hash above; and the registered MiMo route, which must resolve to host `opencode.ai` and model `mimo-v2.6-flash` with a credential present. |
| Analysis (fixed before data) | Plan `vmlu-test-loop-mimo-v1`.<br>• **Outputs.** After each pass the runner writes `loop.jsonl` and `summary.json`. Per item, `loop.jsonl` holds the attempts the rule read, their letters, the rounds and the final answer. Once every item has a final answer, the runner also writes `submission_before.csv` (B-r1) and `submission_loop.csv` (the loop), both `id,answer` for vmlu.ai.<br>• **Scores.** The owner submits the two files to vmlu.ai, and its reported accuracy for each is entered in the run record.<br>• **Primary.** The loop's accuracy minus the before's, descriptive. With item-level gold withheld there is no paired test.<br>• **Descriptive:**<br>&nbsp;&nbsp;– the rounds the loop used, beside MC-105's MiMo VMLU valid rounds (611, 115 and 17 of the 743 items with both B answers);<br>&nbsp;&nbsp;– how many final answers differ from B-r1, and how often B-r1 and B-r2 disagree;<br>&nbsp;&nbsp;– mean reported tokens per item, both B answers included, and latency;<br>&nbsp;&nbsp;– beside the two scores: the /table VMLU Test numbers MC-85 77.68, MC-63 76.20 and MC-89 79.60, and MC-109's Qwen scores 67.09 and 76.63. |

| Comparison limits | • **Before.** The before is the within-run B-r1 at provider defaults, with the /table prompt.
