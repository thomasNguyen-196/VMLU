# MC-94 — Qwen3.5-9B-65K (IEC), router v2 held-out test: B / S on 600 items no router has seen

Registered 2026-10-27 (+07) before benchmark-item requests of this card. The design is `openspec/changes/diagnostic-router-v2`. It does not change MC-90 to MC-93: their registered text, manifests, router v1 and analyses stand.

| Field | Condition |
| --- | --- |
| Why | The single evaluation of router v2, an adaptive router that adds an uncertainty signal to router v1: arm B answers twice, and when the two parsed answers differ the item is escalated to arm S. Router v1 (MC-93) cannot be re-tested on the 60 core anchors, which are now used, so v2 is tested on items that no router has seen. |
| Router v2 | `data/diagnostic_router_v2/router_v2.json`, SHA-256 `0585b9a8980f6b906c2abdbcf69652ee7e8f1c51cca24697f9826d2e4ee26b3a` (`router-v2b-drop-cascade`): Vi-DROP items go to S without a probe; every other item is answered by B twice (agreement rule `normalized-answer-v1`: both parsed answers non-empty and equal, the letter for multiple choice, the exact-match normalization for reading); the first B answer stands when they agree and the item goes to S when they differ. Chosen by the project owner on 2026-10-27 from two candidates committed before their registered fit (commit `ac60b7d`); both policies had been explored on the wide draws while planning. Design fit on wide (mean of two rotations): 56.7% at 1,536 reported tokens per item, against router v1 53.1% at 632, always-S 53.1% at 1,007 and always-B 50.4% at 566. An exploratory check on the used core anchors showed no gain over v1 (61.1% against 62.2%). |
| Scope | 600 items: 300 VMLU valid items drawn per VMLU category in proportion to its size (STEM 110, Humanity 92, Social Science 53, Other 45) and 300 ViBidLQA val items (233 passages), each ranked by sha256(42, dataset:item). Neither dataset belongs to the campaign, so no item was used to design or evaluate a router; both were answered by earlier benchmark runs, so neither is pristine held-out. No Vi-DROP item is in the set, so router v1 sends every item to B here. Arms B and S, two draws each: 2,400 attempts (B 1,200, S 1,200). |
| Protocol and inputs | `data/diagnostic_router_v2/protocol.json`, SHA-256 `8944d367f72952d6edb7f336ce8bbbc8a5f5b341489f70830c455210bf6f5379`, whose model, transport, scoring and budget blocks are those of the campaign protocol (SHA-256 `fe1b1b89d19a93d74dc4b364c64a3308f0c7b6601cf61e90a69533238d80e137`, checked by a test). Prompts: the frozen main-v1 builders (VMLU valid prompts are byte-identical to the main-v1 manifest) and the S template of `prompt_templates_v1.json` (SHA-256 `9bcada89b93a1e011f32379278dae1a8c829cecc2b1c2be4a5740a7ef7df9481`). Manifest `heldout_v1.json`, SHA-256 `c933f94e026765dd3bec18ae608dc0743f909bc5e5685203af036da55155ea44`, run identity `dataset:item:<ARM>-r<k>`. Send no gold. |
| Model / route / connectivity | As MC-90 and MC-93 (see their cards): Qwen3.5-9B-65K served by the IEC internal gateway through the openvpn3 `member-shared-tcp` tunnel, direct API, OpenAI Responses API with streaming, endpoint host resolved inside the runner process through the tunnel DNS. The endpoint self-reports `/home/llm/llama.cpp/models/Qwen3.5-9B-Q4_K_M.gguf`; a change of that id pauses the run. |
| Sampling and limits | As MC-93: temperature 1.0 requested, effective value not observable; seed and reasoning field omitted; system prompt `Answer the user's question.`; `max_output_tokens=4096`; 300 s timeout; no SDK retries. Budget guard 5,000,000 reported tokens for this run (expected about 2 million). |
| Concurrency | Engine of 12 lanes (4 shards x 3 lanes) with at most 4 requests in flight and a breaker that pauses the run after 4 consecutive network failures, registered in `data/diagnostic_router_v2/registration.json` and applied by default; other values are refused. |
| Retries | No in-run retry of a failed item; `--resume` re-attempts only items without a completed response under an identical frozen condition; completed responses, including truncated or unparsed ones, are terminal. |
| Scoring | The scoring of MC-93: B on the raw response with the frozen V1 scorers; S from the text after the last final-answer label (`diagnostic-final-segment-v1`). VMLU is scored by letter; ViBidLQA by exact match, with token-F1 kept. Unparsed answers stay in denominators. |
| Gates | Execution requires the `MC-94` heading in `measurement_card.md`, this detail card, the registration with the held-out protocol, campaign protocol, template and manifest hashes above, the endpoint host and model of the campaign, and `router_v2.json` with the registered SHA-256 and a probe. |
| Analysis (fixed before data) | `analyze_diagnostic_router heldout`, plan `diagnostic-router-v2-heldout-v1`, run once. Per family (multiple choice: VMLU valid, the primary family; reading: ViBidLQA val, secondary) and per rotation: rotation 1 (first B draw answers, second B draw is the probe's second answer, first S draw on escalation) is primary, rotation 2 (the same with the draws swapped) is its replication. Item outcome: the single draw that deployment would return. For v2, always-B (equal to v1 on this set) and always-S: accuracy with a Wilson interval and mean reported tokens per item, both probe answers included whenever the probe ran; exact McNemar of v2 against always-B and against always-S with Holm over the two; escalation share; B and S accuracy where the two B answers agree and where they differ. The confirmatory claim rests on the multiple-choice family in rotation 1 only. Reading adds token-F1 and the items whose correctness differs between v2 and a fixed policy, for an AI-assisted semantic review reported as descriptive. The report's top-level keys are recorded in the registration and checked. |
| Provenance and outputs | `condition.json` with the manifest, protocol, template, rule, runner, engine, wrapper, scorer and card hashes and the operational limits, per-attempt usage and response model id, `operator_events.jsonl` for every launch, all under `all_res/diagnostic_router_v2/heldout/qwen3-5-9b-65k-prospective/`; no upload. |
| Comparison limits | Items answered by earlier runs; no Vi-DROP or Legal MC item, so the Vi-DROP condition and arm K are not tested here; exact match understates reading answers, which is why reading is secondary; single draws at temperature 1.0 are noisy, which the second rotation bounds; the endpoint may have drifted since MC-93, which the model-id check and B's VMLU accuracy against earlier main-v1 runs can reveal; the probe roughly doubles B's prompt cost because the endpoint caches only about 22 prompt tokens. |
