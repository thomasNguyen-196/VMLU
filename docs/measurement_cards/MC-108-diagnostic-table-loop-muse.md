# MC-108 — Muse Spark 1.3 and Muse Spark 1.2 (OpenCode Go), the self-improvement loop on the /table suite, before and after

Registered 2026-11-03 (+07) before benchmark-item requests of this card. The design is MC-105's (`openspec/changes/diagnostic-router-loop`, decision 12), applied to two more students. It does not change MC-90 to MC-107: their registered text, manifests, rules and analyses stand, and the MC-105 modules are imported unchanged.

| Field | Condition |
| --- | --- |
| Why | **The owner's request (2026-11-03).** Run the before-and-after of MC-104 and MC-105 on Muse Spark 1.3 and Muse Spark 1.2, as was done for Qwen and MiMo.<br>**What is known.** On the /table suite, MC-105's loop beat the student's own B in 6 of 12 cells (VMLU valid, Vi-DROP and ViBidLQA for both Qwen and MiMo) and hurt Qwen on Legal MC. On /table both Muse students score above 90% on VMLU valid (Muse Spark 1.3 91.4%, Muse Spark 1.2 91.0%), while Muse Spark 1.2 scores 39.3 token-F1 (v3) on Vi-DROP.<br>**What this card asks.** What the same loop, with the student writing every final answer, does to the numbers of two stronger students. The loop has no parameter fitted to either of them. |
| Students / route | Both on the direct OpenCode Go route of MC-98 and MC-102 (host `opencode.ai`): the Responses API, not streamed, one routing session header per attempt. Input is the system prompt `Answer the user's question.` and the user prompt, as in MC-105's MiMo route and the /table runs MC-82 and MC-84. Temperature, seed and reasoning effort are not sent, so the provider defaults apply. `max_output_tokens=20000`, as in MC-82, MC-84 and MC-105's MiMo. 300 s timeout, no SDK retries.<br>• **Muse Spark 1.3** (`muse-spark-1.3-contributor`, profile `muse-spark-1-3-contributor`).<br>• **Muse Spark 1.2** (`muse-spark-1.2-contributor`, profile `muse-spark-1-2-contributor`). It uses the API root and credential of the Muse Spark 1.3 profile; only the model id differs.<br>One non-benchmark request per model (a one-line question about Vietnam's capital) checked the request shape on 2026-11-03 before registration. Both completed and reported their own model id. The credential comes from the local OpenCode auth store and is never written to outputs. |
| Items | The 2,346 items of the seven columns of the /table before-and-after table.<br>• **The six main-v1 datasets with local gold (2,043):** VMLU valid 744, Legal MC 146, Legal NLI 150 (two options, Có and Không), Vi-SQuAD 200, Vi-DROP 200 and ViBidLQA test 603. | The loop | MC-105's MiMo loop, unchanged (`diagnostic_table_loop.choose` for a student without a probe), replayed offline from the logged answers. The final answer is always one of the student's own logged answers.<br>• **Round 1:** keep B-r1 when B-r1 and B-r2 agree.<br>• **Round 2:** otherwise keep S-r1 when it agrees with one of them.<br>• **Round 3:** otherwise take the majority of S-r1 to S-r3 by normalized answer. A tie goes to the earliest, the earliest attempt with the winning answer is final, an empty answer casts no vote, and with no answer S-r1 is final.<br>• **Agreement:** router v2's normalized-answer-v1 (MC-94). Both parsed answers must be non-empty and equal. Multiple choice compares the letter; reading compares the exact-match normalization of the vi-reading-v3 prediction.<br>• **Nothing fitted.** The loop has no threshold, and no part of it was chosen on a Muse answer. |
| Scoring | **Multiple choice:** the frozen letter parser; S is scored on the line after the last final-answer label, as in the campaign.<br>**Reading:** token-F1 under `vi-reading-v3` (primary; decision 10), with exact match beside it and `vi-reading-v2` beside both. A reply cut at the token cap is scored as it is; an empty reply scores as no answer. |
| Limits | • **Both students:** at most 8 requests in flight each (MC-105's MiMo: 6; MC-82 and MC-84: 12 on another route). A breaker trips after 4 consecutive network failures. The budget guard is 30,000,000 reported tokens each.<br>• **Projection.** About 20 million tokens per student, from the B tokens of MC-82 and MC-84 on these datasets (about 1,200 per reply) and an S reply assumed to be about twice that; no Muse S run exists. The list price is USD 0.10 per million input and 0.20 per million output tokens for both models, so about USD 4 per student. OpenCode Go meters each model separately; this stays under the 5-hour allowance of 20% of a model's monthly limit.<br>• **Time.** About 3 hours for Muse Spark 1.2 and 5 hours for Muse Spark 1.3 at the latencies of MC-82 and MC-84.<br>• **Halts.** Both halt on an authentication error, a permanent provider error, a tool call, or a reported model id that lacks the student's identity token (`muse-spark-1.3` or `muse-spark-1.2`) or changes during the run.<br>• **Resume.** Completed responses, including ones cut at the cap, are terminal; `--resume` re-sends only attempts without one. |
| Gates | Execution requires all of: the `MC-108` heading in `measurement_card.md`; this detail card; `data/diagnostic_router_loop/registration_table_loop_muse.json` with the configuration's SHA-256 and the student's manifest self-hash above; and the student's route (host `opencode.ai` and a credential). The runner rebuilds the student's manifest, re-checking every item against the main-v1 manifest, and refuses to run when it differs. |
| Analysis (fixed before data) | `analyze_table_loop_muse`, plan `table-loop-muse-v1`, run once after both runs. It reuses MC-105's per-item replay, tests and dataset blocks (`analyze_table_loop`) unchanged.<br>• **Per student and dataset (7 datasets):** always-B (B-r1, the before), always-S (S-r1), always-vote (the majority of three S answers) and the loop (the after), each with its score and mean reported tokens; also the rounds the loop used. The loop pays for every request its rounds use, two B answers in round 1.<br>• **Primary test:** the loop against always-B in each of the 14 student and dataset cells, VMLU dev included. Multiple choice uses an exact two-sided McNemar test. Reading uses the mean paired token-F1 difference with a two-sided sign-flip p-value (20,000 resamples, seed 7). Holm corrects over the 14. A cell is met when its Holm p is below 0.05 and the loop scores higher.<br>• **Descriptive:**<br>&nbsp;&nbsp;– loop minus always-S, and always-vote minus always-S, as mean paired differences with a percentile bootstrap interval (2,000 resamples, seed 7);<br>&nbsp;&nbsp;– the number /table publishes beside each dataset (Muse Spark 1.3: MC-80 for VMLU valid, MC-80 with MC-82's recovery for the other five main-v1 datasets, MC-82 for VMLU dev; Muse Spark 1.2: MC-84), from `web/data/benchmark-reports.json`, whose SHA-256 the report records;<br>&nbsp;&nbsp;– MC-105's loop-minus-B for Qwen and MiMo beside each dataset, read from its report, whose SHA-256 the report records;<br>&nbsp;&nbsp;– cost: reported tokens and the list price.<br>The report's top-level keys are recorded in the registration and checked. |
