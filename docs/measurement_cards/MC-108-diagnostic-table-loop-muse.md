# MC-108 — Muse Spark 1.3 and Muse Spark 1.2 (OpenCode Go), the self-improvement loop on the /table suite, before and after

Registered 2026-11-03 (+07) before benchmark-item requests of this card. The design is MC-105's (`openspec/changes/diagnostic-router-loop`, decision 12), applied to two more students. It does not change MC-90 to MC-107: their registered text, manifests, rules and analyses stand, and the MC-105 modules are imported unchanged.

## Amendments 1–4 (2026-11-04, decided by the owner during the run; the registered text above is unchanged)

The four amendments are recorded under `amendments` in `data/diagnostic_router_loop/registration_table_loop_muse.json`. Their text is added here only now, because the SHA-256 of this card is part of the frozen run condition and an edit during the run would have stopped `--resume`.

| Field | Amendment |
| --- | --- |
| What happened | On 2026-11-03 the provider's content filter refused step-by-step (S) prompts with HTTP 400 `content_policy_violation`. Muse Spark 1.2 was refused twice on Vi-DROP 1467 (15:06 +07). Muse Spark 1.3 was refused once on Vi-SQuAD 2629 (14:59), with the code not logged; that attempt completed when re-sent. The operator re-sent the S-r1 prompt of Vi-DROP 1467 once outside the ledger, to read the error code, and it was refused again. At 15:08 both models returned 403 `user_blocked` ("repeated policy violations"). Access returned on 2026-11-04 (non-benchmark pings at 16:04 +07). The registration did not say what to do when a prompt is refused. |
| Amendment 1 (16:05) | Vi-DROP 1467 and Vi-SQuAD 2629 are held out for both students. Attempts of a held-out item without a completed response are not sent, completed rows stay in the ledger, and a refused attempt is never re-sent. The runner also changed in three ways that do not change what is sent: one attempt per item in flight (a refusal halts the run before the item's next prompt), replicate-major send order, and the provider's error code logged from the error body (never the message). |
| Amendment 2 (16:12) | After Muse Spark 1.2 refused Vi-DROP 3101 (16:08, a passage on helicopter losses), the 35 Vi-DROP items whose passage matches a registered war, weapons and drugs pattern are held out for both students. Vi-SQuAD passages matching the pattern stay in (1 refusal in 110 S prompts). |
| Amendment 3 (16:19) | After Muse Spark 1.2 refused Vi-DROP 5218 (16:16, an airliner crash with 100 deaths, not matched by the pattern), all of Vi-DROP is held out for both students. |
| Amendment 4 (16:39) | After Muse Spark 1.2 refused Vi-SQuAD 1855 (16:23, a passage on weather forecasting), Muse Spark 1.2 is stopped for good. Muse Spark 1.3 continues, but its first refusal after 2026-11-04T09:39:37Z stops MC-108 for good, and the runner then refuses every launch. |
| Scoring | Not decided. The registered analysis is not run (see the run record). |
| Timing | Each amendment was decided by the owner after a refusal and before any further benchmark request. No score of this card had been computed. |
