# MC-89 — MiMo V2.6 Flash, OMP full tools, MC-85/86/87/88 matched scope, 900 s timeout

Registered 2026-10-19 (+07) before benchmark-item requests. Fourth arm of the full-tools program: run OpenCode Go MiMo V2.6 Flash on the same item scope as MC-86/R2, MC-87 and MC-88 under the same OMP controls, with the 900-second item timeout the user selected for continuity with MC-88.

| Field | Condition |
| --- | --- |
| Model / route | MiMo V2.6 Flash, OMP model ref `zen-go/mimo-v2.6-flash`, OpenCode Go **Chat Completions**. The gateway rejects the Responses protocol for this model (`ModelProtocolUnsupported`) and requires an `x-opencode-session` header on both protocols (both probed 2026-10-19 before registration). Keep MC-54/59/63/67 (older OMP no-tools runs) and MC-85 (API direct) separate: different harnesses and budgets. |
| Harness | OMP 18.0.0, JSON mode; OMP full default tool menu; default coding-agent system prompt; auto-approve; no session, title, extensions, skills, rules, or LSP; one isolated process and scratch directory per item with a stable per-item `x-opencode-session` routing header. |
| Credential boundary | Resolve `OPENCODE_GO_API_KEY` in the parent process (environment or the local OpenCode auth store) and forward model requests through a loopback streaming relay. OMP and its tools receive only an ephemeral local relay key. |
| Item isolation | Run OMP in a Bubblewrap user/PID/mount namespace. Bind only the item scratch, isolated OMP profile, fake HOME, and read-only runtime files; keep network available for the model relay and full tools. The host home, repo, datasets, and gold files are not mounted. |
| Scope | The same 12,033 MC-85 items as MC-86/R2, MC-87 and MC-88: VMLU Valid 744, Legal NLI 150, Vi-SQuAD 200, Vi-DROP 200, ViBidLQA Test 603, VMLU Dev 303, and VMLU Test 9,833. Legal MC 146 stays excluded via the MC-71 exclusion ledger, verified by ID and prompt hash. No V-Bench or pilot items. |
| Inputs and prompts | Freeze the MC-85 manifests and item order; preserve every frozen user prompt byte-for-byte; send no gold. Local gold is retained only for local scoring. |
| Sampling | Temperature 1.0 set in the isolated OMP profile; MiMo's thinking mode runs the provider default and may ignore a custom temperature. Thinking `auto`; the model emits reasoning by provider default (a probe returned `reasoning_tokens`); reasoning effort not pinned; seed omitted. |
| Token and time limits | Model `maxTokens=20000` per assistant turn (same as MC-86/87/88). Item timeout 900 seconds plus a 60-second subprocess margin — the user's choice for continuity with MC-88 on 2026-10-19; the MC-86/87 nominal was 300 s, so comparisons against the Muse arms must retain this difference. OMP can make multiple assistant calls per item; retain all reported usage. |
| Workers and scheduling | 12 worker threads pulling from one global queue ordered by the frozen manifests. A worker takes the next pending item when its current item ends, including items from another dataset. No fixed worker-to-dataset assignment. Record worker ID, dataset, active peak, and item timing. |
| Retries | No SDK retries. Retry only failed technical attempts identified as transient, up to three total attempts; completed responses, truncations, and unparsed answers are terminal. Never retry for correctness. Stop on authentication, permission, billing, or model-configuration errors. |
| Scoring | Frozen V1 scorer for Main local-gold datasets and frozen V2 scorer for Dev/Test. Keep unparsed model responses in local-gold denominators. Test gold remains withheld; no local Test accuracy is claimed. Create a local `id,answer` Test submission only after complete Test coverage; do not upload it. |
| Provenance and outputs | Record MC-85 parent manifests, prompt hashes, MC-71 exclusion ledger hash, condition/card/runner/scorer hashes, the MiMo registry profile hash, per-attempt usage and tool audit, and all output files under `all_res/mimo26_omp_mc89/`. OMP preflight is a non-benchmark request and is excluded from the 12,033 items. |
| Comparison limits | Fourth descriptive arm of the OMP full-tools group. The chat protocol differs from the Muse arms (Chat Completions vs Responses) and the 900 s timeout override differs from their 300 s nominal; provider effective temperature/reasoning tiers remain unknown. Historical MiMo no-tools and direct conditions are not interchangeable with this arm. OpenCode Go availability is region-limited; the OMP preflight must return usable content before workers start. |
